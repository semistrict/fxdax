## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Service for the Go daemon: tenants (create, delete), stores (create, import an image, fork, delete, resize, place, sync, stat), grants, stats. Errors as gRPC statuses carrying errnos. Replaces the custom socket's control requests (FORK_PATH, DELETE_PATH, RESIZE, SYNC_PATH, STATS) for callers outside VM processes.

## Implementation Plan

5. fxdax-extentd serves it at FXDAX_EXTENTD_GRPC.
6. tests/control.rs: a Rust client exercising every RPC, against a daemon on threads.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Dependencies (licenses checked, versions via cargo add): tonic, tonic-prost, tonic-prost-build 0.14.6 (MIT), prost 0.14.4 (Apache-2.0), protox 0.10.0 (MIT OR Apache-2.0), tokio-stream 0.1.19, hyper-util 0.1.21, tower 0.5.3 (MIT). Runtime deps are Linux-only, as extentd is.

Decisions:
- Tenants are not RPCs of their own: Grant (TASK-43.4) makes a tenant and its socket, Revoke removes it once its connections are gone and its arena's cached pages evicted. Moved there.
- The custom socket's control requests (FORK_PATH, DELETE_PATH, RESIZE, SYNC_PATH, STATS) stay until TASK-43.5 moves fxdaxctl to gRPC, then go.
- A store whose VM process is gone, still closing, counts as not open: stat, fork and sync wait for it to be let go (Held) rather than act on the closing store.
- Errors: gRPC codes from errnos, the errno itself in the fxdax-errno metadata entry (control::errno reads it).

Validation: tests/control.rs (stores_through_the_control_api, open_stores_are_their_vms, imports_images) exercise all 10 RPCs, on Lima. scripts/test.sh macOS 2011 passed, Lima 2044 passed; guest e2e extent-guest, fxfs-guest-dax, fxfs-guest-snapshot-dax OK; upstream-changes --check and license-headers OK; cargo clippy -p fxdax --no-deps: no new warnings (clippy without --no-deps fails in zircon, pre-existing: absurd_extreme_comparisons at vm_address_region.rs:509).

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
extentd serves a gRPC control API (fxdax.extentd.v1, crates/fxdax/proto) over a Unix socket at FXDAX_EXTENTD_GRPC: CreateStore, ImportImage, ForkStore, DeleteStore, ResizeStore, PlaceStore, MakePublic, SyncStore, StatStore, GetStats. Blocking store work runs on spawn_blocking; errors are gRPC codes carrying errnos. The path-level store operations moved into extentd/stores.rs first (refactor commit), shared by VM connections and the API. Verified by tests/control.rs, a Rust client exercising every RPC, plus full suites on macOS and Linux and guest e2e.
